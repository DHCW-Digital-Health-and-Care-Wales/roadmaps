# Choose useful verification

Read `package.json`, each touched app's manifest and tool configuration
(`apps/editor/package.json`, `vite.config.ts`, `playwright.config.ts`,
`eslint.config.ts`; `apps/public-site/package.json`, `vite.config.ts`,
`playwright.config.ts`, `eslint.config.ts`; `apps/api/package.json`,
`pyproject.toml`) and `.github/workflows/ci.yml`.
The commands below identify families; the scripts remain authoritative. Run
from the repository root.

The full gate before a PR runs what CI runs for the change: the root's
`pnpm format:check && pnpm repo:typecheck && pnpm repo:lint && pnpm repo:test`, then
the gate of each app that `scripts/ci/classify-changes.sh` marks for the changed paths
(`git diff --name-only <base> | scripts/ci/classify-changes.sh`), so a root file that
runs every app's CI jobs runs every app's gate:

| App         | Its gate                                                                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| editor      | `pnpm editor:typecheck && pnpm editor:lint && pnpm editor:test && pnpm editor:build && pnpm editor:test:e2e`                                                        |
| public site | `pnpm site:typecheck && pnpm site:lint && pnpm site:test && ROADMAPS_DATA=e2e/fixtures/roadmaps.json pnpm site:build && pnpm site:test:e2e && pnpm site:lighthouse` |
| API         | `pnpm api:lint && pnpm api:typecheck && pnpm api:test`; `api:test` starts the slot's database in Docker, as `api:dev` does                                          |

Report executed test counts and failures; zero tests or a skipped check is not
validation. Preserve runner exit status when redirecting output. Capture
verbose logs in a temporary path and summarize the evidence.

A test that times out at its budget in a gate run and passes when its file runs
alone, on the same head, is a flake only if your change has not slowed it: an
open defect records it timing out without your change and its time alone is
close to the time recorded there, or it times out the same way on your base.
Add the run to that defect, or record one (`docs/AGENTS.md`, with
`pnpm format:check && pnpm test:docs`), then run the gate's commands after the
one that failed; with them green, the head has passed the full gate. Classify
any other failure that passes alone as `pr-watch.md` does (_Each event or
observation_).

Stop any stale `pnpm editor:preview` or `pnpm site:preview` on the checkout's
preview port (`fuser -k <port>/tcp`; see `apps/editor/AGENTS.md` and
`apps/public-site/AGENTS.md`) before running Playwright E2E, since Playwright
reuses a server already listening there locally.

Give a suite you wait for in the foreground a command timeout longer than its
run; under host load the Vitest run alone outlasts a runtime's default (2
minutes in Claude Code). For a run that can outlast the runtime's longest
foreground timeout, the full gate among them: where the runtime wakes you when
a background command completes, start it in the background with its exit
status in its output and yield until it completes, once independent work is
exhausted, as for a reviewer (`delegation.md`, _Dispatch and completion_, step
3); otherwise run its commands as separate foreground calls, each within that
timeout. To work alongside a suite, start it in the background, leave the
checkout's files as they are until it ends, since it reads them (a
deliberate break or a fix made meanwhile fails it, or passes a tree that is
not the head), and read its exit status before relying on it.
Detach only a run that must outlast the session, with output and exit status
in a log (`setsid nohup sh -c '<cmd>; echo "exit=$?"' > /tmp/<name>.log 2>&1 &`),
and read that log before relying on it.

A fix made between review rounds, before it is pushed, needs the tests of its
changed files and their consumers (`cd apps/<editor|public-site> && ./node_modules/.bin/vitest related --run <files>`, with `<files>` relative to the app; for the API, `pnpm api:test`, or `cd apps/api && uv run --locked pytest <test_file>` for one non-DB file since `pnpm api:test` enforces 100% package coverage),
with `pnpm lint`, `pnpm typecheck` and `pnpm format:check`, plus the Playwright
specs of any journey it changes; with those green, commit it and start the next
round's reviewers. Every head you push gets the full gate first, on its
current base: fetch the base before that gate and rebase when it has moved
(`pull-requests.md`, _Update a branch_), since a base found moved at the push
costs the gate again. A head that differs from one that passed it only in
Markdown needs just its table rows, with `pnpm format:check` and
`pnpm test:docs`: of the gate, only those read Markdown. A rebase onto a base
that changed only Markdown makes such a head.

CI is the shared merge gate, and independent review covers requirements and
judgement beyond deterministic checks. Never rely on one as a replacement for
the other, or claim prose instructions technically enforce an agent's
behaviour.
