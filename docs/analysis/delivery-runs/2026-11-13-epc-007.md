## Learnings and next evaluation

- What helped:
  - Per-item orchestrator threads, once #44 required them: sessions 2 to 4 each ran one
    item with a compact handoff.
  - Merging between items kept every delivery on a fresh `main`; STY-032 and STY-033 went
    from dispatch to merge in about 25 min each.
  - Every CI run that completed on the four PRs passed; the runs cancelled were superseded
    by a newer push.
- Avoidable cost:
  - The single-thread queue in session 1, now fixed by #44.
  - On #49 the orchestrator removed its PR watch while the merge call had not landed. The
    owner had taken the merge over, so the watch's loss cost nothing here, but
    `pr-watch.md` step 4 told it to remove the watch "when done", a state defined before the
    merge. This run's retro PR replaces that with the PR reading merged or closed.
  - Not changed, as outside orchestration guidance or already covered: the Claude API
    outage, the Codex credit limit (the owner's reroute is required by the runtime's rule
    against switching providers unasked), the GitHub merge incident, and the conflict on a
    pushed branch (the session-start hook already says to merge `main` in and never
    force-push).

    (Needs triage).
