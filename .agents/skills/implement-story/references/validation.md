# Choose useful verification

Read `package.json`, the tool configuration (`vite.config.ts`,
`playwright.config.ts`, `eslint.config.ts`) and `.github/workflows/ci.yml`.
The commands below identify families; the scripts remain authoritative. Run
from the repository root.

The full gate before a PR is
`pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm build && pnpm test:e2e`.
The table says what each kind of change additionally needs.

| Changed contract             | Required evidence                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain or `lib/`             | Unit regression first; for a `RoadmapRepository` change, both implementations pass `describeRoadmapRepositoryContract` (the Sheets adapter and the in-memory double in `features/roadmaps/testing/`)                                                                                                                                                                  |
| Infrastructure (Sheets, GIS) | MSW-backed unit tests for each HTTP status and malformed body the adapter maps (Zod at the boundary); the E2E fakes in `tests/e2e/fixtures/` updated in step, since they record wrong paths, `fields`, scopes or tokens as violations                                                                                                                                 |
| Auth state or token handling | State-machine tests for each transition touched; the E2E token guard (`tests/e2e/fixtures/persistence-recorder.ts`) still passes; `connect()` still runs synchronously in the click handler (the GIS fake records a call outside a user gesture)                                                                                                                      |
| Features, components, routes | Component tests through `renderWithProviders`; Playwright coverage for each changed journey; screenshots per `screenshots.md`; `src/routeTree.gen.ts` regenerated by `pnpm build` and committed when routes change                                                                                                                                                    |
| Copy                         | `copywriter` judgement; both catalogues (`en.ts`, `cy.ts`); `pnpm typecheck` (catalogue parity and key types) and `pnpm lint` (`i18next/no-literal-string`); a Welsh rendering in at least one test                                                                                                                                                                   |
| Visible UI                   | Light and dark, desktop (1280 px) and phone (375 px) where layout changes; for a changed row of controls, an E2E test in Welsh at each breakpoint's width (640 px `sm`, 768 px `md`, 1024 px `lg`); the axe spec (`tests/e2e/accessibility.spec.ts`) for new states                                                                                                   |
| Build, chunks, base path     | `pnpm build` with no new warnings; for base-path work also the E2E suite under `VITE_BASE_PATH=/roadmaps-editor/` (CI runs it that way)                                                                                                                                                                                                                               |
| CI workflows, Dependabot     | `actionlint` (not a dependency; download the release binary ad hoc); actions stay pinned to commit SHAs with the version in a comment; observe a changed job before review by pushing the branch and running `gh workflow run ci.yml --ref <branch>` (the workflow has `workflow_dispatch`), then reading its steps with `gh api repos/<repo>/actions/runs/<id>/jobs` |
| Dependencies                 | `pnpm install --frozen-lockfile` from a clean `node_modules`; keep `@playwright/test` pinned exactly to the installed browser revision                                                                                                                                                                                                                                |
| Rules, skills, agents, hooks | First check whether a type, an existing ESLint rule or a test already covers the rule; a new check states its rung and where it runs. Then `pnpm format:check` and the skill's own script tests (`node --test '.agents/skills/<skill>/scripts/*.test.mjs'`)                                                                                                           |
| Configuration values         | For a value with no behaviour of its own (a retry count, a stale time, a chunk group, a CI job graph), an observed run showing the effect (log line or run URL) in the record's Delivery, under Scenario evidence, not a test restating it; behaviour a value delivers keeps its regression test                                                                      |
| Documentation only           | Read every deleted line in `git diff` before committing a scripted edit; `pnpm format:check && pnpm test:docs` (CI's Docs job). Verify factual claims against source; an owner's answer, a moved obligation or an edited scenario needs the `docs/AGENTS.md` sweep, shown as the greps run                                                                            |

Report executed test counts and failures; zero tests or a skipped check is not
validation. Preserve runner exit status when redirecting output. Capture
verbose logs in a temporary path and summarize the evidence.

A test that times out at its budget in a gate run and passes when its file runs
alone, on the same head, is a flake only if your change has not slowed it: an
open defect records it timing out without your change and its time alone is
close to the time recorded there, or it times out the same way on your base.
Add the run to that defect, or record one (`docs/AGENTS.md`, with
`pnpm format:check && pnpm test:docs`), then run the gate's commands after the
one that failed; with them green, the head has passed the full gate. Classify
any other failure that passes alone as `pr-watch.md` does (_Each event or
observation_).

`pnpm test:e2e` builds and serves the app on port 4173 (in a parallel
worktree, its `PREVIEW_PORT`: `pnpm worktree:info`) and reuses a server
already listening there locally: stop a stale `pnpm preview` first
(`fuser -k <port>/tcp`).

Give a suite you wait for in the foreground a command timeout longer than its
run; under host load the Vitest run alone outlasts a runtime's default (2
minutes in Claude Code). For a run that can outlast the runtime's longest
foreground timeout, the full gate among them: where the runtime wakes you when
a background command completes, start it in the background with its exit
status in its output and yield until it completes, once independent work is
exhausted, as for a reviewer (`delegation.md`, _Dispatch and completion_, step
3); otherwise run its commands as separate foreground calls, each within that
timeout. To work alongside a suite, start it in the background, leave the
checkout's files as they are until it ends, since it reads them (a
deliberate break or a fix made meanwhile fails it, or passes a tree that is
not the head), and read its exit status before relying on it.
Detach only a run that must outlast the session, with output and exit status
in a log (`setsid nohup sh -c '<cmd>; echo "exit=$?"' > /tmp/<name>.log 2>&1 &`),
and read that log before relying on it.

A fix made between review rounds, before it is pushed, needs the tests of its
changed files and their consumers (`pnpm exec vitest related --run <files>`),
with `pnpm lint`, `pnpm typecheck` and `pnpm format:check`, plus the Playwright
specs of any journey it changes; with those green, commit it and start the next
round's reviewers. Every head you push gets the full gate first, on its
current base: fetch the base before that gate and rebase when it has moved
(`pull-requests.md`, _Update a branch_), since a base found moved at the push
costs the gate again. A head that differs from one that passed it only in
Markdown needs just its table rows, with `pnpm format:check` and
`vitest run build/markdown-links.test.ts build/agent-guides.test.ts`: of the
gate, only those read Markdown. A rebase onto a base that changed only
Markdown makes such a head.

CI is the shared merge gate, and independent review covers requirements and
judgement beyond deterministic checks. Never rely on one as a replacement for
the other, or claim prose instructions technically enforce an agent's
behaviour.
