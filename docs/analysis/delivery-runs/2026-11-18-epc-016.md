## Learnings and next evaluation

- Totals: 12 reviewer tasks. Accepted: no P0 or P1; 1 P2, 3 P3, 7 🟡 and 8 💭, all fixed;
  2 declined with reasons, 3 💭 left. Opus and Sol found STY-067's P2 independently. No
  escape after the reviews' last head; both merged heads passed CI first time.
- What helped:
  - Merging between items put STY-067 on STY-066's measured cut, which its opened rows
    reuse, as the shared brief told it.
  - The re-check lane caught a new P3 that a round-1 fix introduced (STY-067).
- Avoidable cost:
  - A delivery child left idle mid-delivery, on both items and with both delivery models.
    `orchestrate`'s fallback-wake branch ended the turn whenever no hand-back was recorded,
    which never recovers a child that is terminal; both orchestrators sent it a message
    instead, and the first wrote that into the shared brief. Stall durations are unknown:
    no source timestamps when the child went idle or resumed; the fallback wake ran every 15
    minutes. What left the child idle is unrecorded.
  - A rebase and full gate after a parallel queue's story merged on `main` (about 18
    minutes from rebase to green CI). The retro judged it required: the base moved with
    code before the hand-back.
- Orchestration retro, in this record's PR: `orchestrate` step 3 item 2's fallback-wake
  branch now also runs on an interim completion, and reads the child's runtime status when
  no hand-back is recorded: a terminal child without one has stalled, so the orchestrator
  messages it to continue from its handoff, or replaces it where it cannot. The per-item
  retros judged this covered by the line that a yielded turn with live descendants is not
  a completed item; that line covers the opposite case. Considered and left as they are:
  - The rebase and re-gate: `validation.md` and `pull-requests.md` already require it.
  - The stale check event: `pr-watch.md` already reconciles each event against the current
    head, and the orchestrator did.
  - A background gate with no task to wait on: the runtime's, not the repository's; the
    scheduled wake covered it.
  - Interim yields themselves: told from the hand-back each time, as in earlier runs.
- Follow-up work: none.
- Next comparison: on the next queue, whether a stalled child is messaged at the interim
  completion or first wake that finds it terminal, and how long a delivery sits idle before
  that, logging both times so the stall is measured, as this run's was not.
